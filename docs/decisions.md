这里只保留会影响后续维护的原因、约束和证据。当前调用方式见各实现专题；下面的历史结果不等于持续有效的线上保证。

## 架构与交互取舍

| 决策 | 保留它的原因及代价 |
| --- | --- |
| 单 `:app` 模块，按功能和职责分包 | 早期优先减少小型个人项目的构建与接线成本。当前不是强制模块隔离，后续拆分应由实际耦合问题驱动。 |
| 选择 Terminal 视觉方向 | 早期比较多个视觉原型后采用深色、等宽、少圆角的统一语言。现有主题和共享组件才是实现依据；未采用的 HTML 设计稿不再常驻仓库。 |
| 课程保存为展开后的每次事件 | 简化日／周显示、单次删除和提醒，放弃通用 RRULE 引擎。导入位图与手工连续周最终落为相同数据结构。 |
| 扫描统一文档编辑器（2026-06） | 原“待完成构建器／已完成详情”造成加页、取消和恢复路径分叉。现在新建、已有文档共用入口，只清理本次新建的空文档，已有文档不会因返回而丢失。 |
| 多图复用旧消息列（2026-06） | 单路径升级为 JSON 数组时保留旧值解码，避免为这一变化触发数据库重建。字段名未改不代表仍只支持一张图。 |
| 知识整理先草稿后确认 | 模型可能选错类别、题面或关联，用户确认后才持久化。知识库复制图片，避免删除聊天／扫描时破坏已保存条目；重新生成仍依赖来源。 |
| 学校复杂验证交给官方网页（2026-09） | 复用学校短信、风控交互，减少自行维护私有验证表单的范围。代价是 WebView 与原生必须共享 Cookie，并在返回后重新验证，不能仅靠页面关闭判断成功。 |
| 短信二次验证与图形验证码改为 App 内完成（2026-11） | 最常见的“密码对了还要短信”在原生面板里完成，不再整页跳到学校网页。接口按学校当前前端脚本实现，网页弹窗保留为兜底：原生处理不了或用户选择时，仍走上一条的网页验证。 |

早期选择了开发期破坏式 Room 升级；这个配置仍在，但不构成后续清空用户数据的授权。继续发布时需要真实迁移方案，见[架构边界](architecture.md#数据与配置)。

## 教务协议中已被推翻的假设

2026 年 5 月最初的导入实现曾在单元测试通过后连续遇到协议错误；9 月校外修复又暴露了网关与服务会话的区别。需要长期保留的教训如下：

| 当时的假设／症状 | 实际原因与现在应遵守的规则 |
| --- | --- |
| 所有 CAS 都使用常见表单和 CBC 加密 | BIT 页面字段是 `login-page-flowkey/login-croypto`，密钥需 Base64 解码，密码按学校协议用 AES-ECB。协议不能从同类学校模板推断。 |
| POST 到旧域名后跟随 302 即可 | 旧认证域名迁移会使 POST 经 302 转为 GET，丢失请求体；应向实际 CAS 地址、带正确 service 提交。教学中心 service 还包含本次 nonce。 |
| 响应不含“用户名密码”就是成功 | 空的 `body()`、非 2xx 错误体、短信页和中间页都可被误判。该启发式已废弃，必须检查 ticket、匹配的回调及落地响应。 |
| CAS、教学中心、jwms 可以当作一个登录态 | 它们有独立服务会话，校外还多一层 WebVPN。目标 ticket 不能在网关准备前消费，再拿已用票据重试。 |
| Cookie 按名字或 `(domain, name)` 去重足够 | WebVPN 把不同目标放到同域不同路径，同名 Cookie 必须保留 path；新值应覆盖旧值，并遵循标准 domain/path/secure 匹配。 |
| 登录成功就能直接请求所有模块 | `wdkbby` 需要 app 预热；考试有独立落地页。一次 CAS 成功并不等于所有业务端点已准备好。 |
| 找不到成绩表等于没有成绩 | 可能拿到了登录页或错误页。成绩的无表响应现在报异常，避免误报空数据或清掉旧数据；其他功能还需要同样审视。 |
| 一个 HTTP 200 或教学中心可达就证明在校内 | 公网认证页也会返回 200，且教学中心可达不代表 jwms 可达。当前探测不跟随跳转，只接受 jwms 的 2xx，仍不能代表所有服务。 |

考试数据源先从假设的 jsxsd HTML 改为 `studentWdksapApp`，9 月又改到当前 `wdksapMobile`。成绩则由假设的 ehall JSON 改为 jwms HTML。维护时查当前 Service／UseCase 和脱敏真实响应，不要把曾经能用的路径永久固化在设计文档里。

旧调试记录曾建议完整 BODY 日志；现在不保留这种常规操作方式。学校日志限于阶段、方法、host/path、状态等必要信息，票据、Cookie、验证码、密码和日历 token 不进入共享日志或 fixture。

## WebView 与跳转故障

2026-09 的真机验证曾出现白字浅底、学号正序输入却倒序保存。排查发现 WebView 根元素与背景容器高度为零，输入后光标回到零位置；显式设置 `MATCH_PARENT` 布局后高度及输入恢复。这个问题说明：页面背景已下载、DOM 已加载，并不能证明宿主视图的测量和输入行为正常，不能只用换颜色掩盖布局问题。

短信通过后曾落到错误的 `sso.bit.edu.cn/cas/<WebVPN编码>/wengine-vpn-token-login`，CAS 返回 404，而网关会话实际已建立。当前只对这一特定来源、路径和状态做一次返回 WebVPN 根入口的恢复，不重放 token POST，也不将恢复跳转视为认证成功。恢复后仍须原生验证。

另一次成绩登录已到 `main.jsp`，却被程序跳回入口：原因是宽泛正则误把网页退出函数里的 `location` 当成自动跳转。现在仅匹配完整的独立字面量跳转脚本，保留函数／事件处理器反例测试。不要通过不断扩展宽泛的跳转正则来“兼容所有网页”。

当前实现入口：[BitWebVerificationDialog](../app/src/main/java/com/example/personal_studio/feature/auth/ui/BitWebVerificationDialog.kt)、[BitAuthPages](../app/src/main/java/com/example/personal_studio/data/network/bit/BitAuthPages.kt)。

## 本地功能中值得保留的经验

- **中文检索需在设备上验证。** Android SQLite 的 tokenizer 与 FTS 查询语法曾与预期不同。当前选择 FTS4 `unicode61` 配合手工 bigram，隐式 AND 不足时再查 OR，避免依赖设备未启用的扩展语法。索引必须跟随主记录一起更新／删除。
- **图像预处理影响检测质量。** 高分辨率拍照图缩小到模型输入时的混叠会让拍后检测差于取景检测，改用面积插值比盲目调阈值有效。扫描滤镜超采样改善细字，也显著增加内存，效果和内存必须一起评估。
- **公式高度会在字体加载后变化。** KaTeX 渲染不能只测一次高度，CSS px／dp 也不能二次缩放。保护公式分隔符、等待页面就绪、观察高度及销毁 WebView 是同一条稳定渲染链。
- **FTS 与图片不是普通外键对象。** FTS 需要显式维护；图片文件与数据库不能自动原子提交。文档中的“事务”应明确指数据库操作，不能覆盖文件副作用。
- **WorkManager 不适合准点提醒。** 历史设备上曾因 Doze／厂商后台管理，直到重新打开应用才批量通知。单项提醒因此改用 AlarmManager，WorkManager 保留给轮询与重排；没有精确闹钟权限时仍会延迟。
- **PendingIntent 的 extras 不参与身份匹配。** 不同提醒必须把事项和档位写入 data URI，否则后排的闹钟可能覆盖先前闹钟。完成／删除后接收器还会查库，避免残留闹钟误通知。

对应实现及约束集中在[学习工具](learning-tools.md)和[日程与提醒](timeline.md)，不再保存旧版完整代码示例。

## 成绩统计的解释边界

学校单课详情中的百分位采用“前 p%”，**越小越靠前**。整体专业百分位估计不能简单平均这些百分位，也不能把每门课当成独立样本来夸大总排名。

[`RankPercentileEstimator`](../app/src/main/java/com/example/personal_studio/core/util/RankPercentileEstimator.kt) 将每课百分位转入 z 空间后按学分加权，点估计采用相关性 `ρ=1` 的保守模型；区间结合各课分歧和 `ρ_min=0.5` 的相关性敏感度。至少需要两门有效课，结果限制在前 1%–99%。这是模型假设下的参考范围，**不是经真实总体排名校准的置信区间**，不能写成学校官方名次。

[`PeerGpaEstimator`](../app/src/main/java/com/example/personal_studio/core/util/PeerGpaEstimator.kt) 处理“均分换绩点”的非线性问题：直接把课程均分代入凹的绩点函数，会高估按个人绩点再求平均的结果。当前用最高分和人数估计离散程度，再作二阶修正；缺少这些数据时退化到均分换算。各课人群、低分截断和分布假设仍限制了准确性，所以界面称它为“估计平均水平”。
